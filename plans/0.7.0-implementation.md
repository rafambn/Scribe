# Implement Scribe 0.7.0

## Outcome

Release-ready code on `dev-0.7.0` that publishes the `scribe` core for the 22 targets below. Keep `scribe-slf4j` JVM-only. Set both modules to version `0.7.0`.

The work stops at validated source changes. Do not commit, tag, create a GitHub release, or publish artifacts.

## Target contract

Configure these targets in `:scribe`:

- JVM: `jvm`, `android`
- Web: `js`, `wasmJs`, `wasmWasi`
- Android Native: `androidNativeArm32`, `androidNativeArm64`, `androidNativeX86`, `androidNativeX64`
- Apple: `iosArm64`, `iosSimulatorArm64`, `iosX64`, `macosArm64`, `tvosArm64`, `tvosSimulatorArm64`, `watchosArm32`, `watchosArm64`, `watchosDeviceArm64`, `watchosSimulatorArm64`
- Other Native: `linuxArm64`, `linuxX64`, `mingwX64`

There must be exactly 22 targets. Exclude the Kotlin-deprecated `macosX64`, `tvosX64`, and `watchosX64`. Also exclude `linuxArm32Hfp`, which is not in the dependency intersection.

Configure both browser and Node environments for `js` and `wasmJs`. Configure Node for `wasmWasi`. Publish only through the existing Maven Central setup. Do not add npm publishing.

Keep Kotlin `2.4.10`, kotlinx.serialization `1.11.0`, and kotlinx.coroutines `1.11.0` unless the build proves that a version change is required. If a change is required, report the evidence before expanding scope.

## Error-hook contract

Keep the public `onIgnition` behavior and make its lifecycle explicit:

- Register it on the first `hire()` for that `Scribe`.
- Unregister it during `retire()`.
- If several active `Scribe` instances configure `onIgnition`, deliver each global error once to every active callback.
- Install at most one platform-level dispatcher per process or global environment. Restore or detach the previous platform handler after the last callback unregisters.
- Observe failures without suppressing or replacing the runtime's normal termination behavior.
- Treat delivery during a fatal error as best effort. Do not block or promise to drain the asynchronous Scribe buffer.
- Preserve previous handlers even when a Scribe callback throws.

Platform behavior:

- JVM and Android use the platform uncaught-thread mechanism.
- Native uses Kotlin's unhandled-exception hook.
- Browser JS and browser `wasmJs` observe synchronous global errors and unhandled Promise rejections.
- Node JS and Node `wasmJs` observe uncaught exceptions without changing Node's default exit behavior, and observe unhandled Promise rejections.
- `wasmWasi` has no portable hook. If `onIgnition` is non-null, `hire()` must fail with a clear unsupported-operation message. Normal Scribe behavior must work when `onIgnition` is null.
- Wrap non-`Throwable` JavaScript rejection reasons in a Kotlin exception with a useful message.

Choose the smallest source-set hierarchy that expresses these behaviors without platform checks in `commonMain`. Keep every new top-level class, interface, enum, or object in its own file.

### 3. Implement global error registration

Refactor the internal expect/actual boundary as needed to support registration plus unregistration. Keep global-state ownership internal. Complete when every locally runnable test passes and every target has a successful compilation or a precisely documented host limitation.

Run the broadest build that the current host supports after all edits. Run focused Web, Wasm, lifecycle, and SLF4J tests separately when the broad build does not execute them. Inspect `git diff --check`, the final diff, and the working tree for generated files or unrelated edits.

## Guardrails

- Use the `kotlin-specialist` skill and its KMP and coroutine guidance.
- Preserve coroutine cancellation. A retiring Scribe must cancel its owned scope only after accepted work completes as the existing contract requires.
- Keep the solution direct. A small internal registry is acceptable; a public framework for platform hooks is outside scope.
- Public API breaks are allowed when required for this target work, but lifecycle, buffering, and archivist APIs are otherwise unchanged.
- Use `bun` for any standalone JavaScript tooling. Prefer Kotlin Gradle tasks for Kotlin/JS and Kotlin/Wasm tests.
- Prefix shell commands with `rtk`, except `./gradlew` commands.
- Preserve unrelated user changes if any appear during implementation.
